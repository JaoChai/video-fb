# ช่วงคอนเทนต์พื้นฐาน 15:00 — Design Spec

วันที่ 2026-07-28 · สืบเนื่องจาก `2026-07-25-fb-tutorial-content-design.md`

## 1. เป้าหมาย

เพิ่มคลิปวันละ 1 ใบเวลา **15:00** สอนพื้นฐาน Facebook Ads จากหน้าจอจริง
(ฟีเจอร์ที่ต้องใช้ + วิธีอ่านรายงาน) เพราะคนจำนวนมากยังไม่เข้าใจพื้นฐาน

**ลำดับความสำคัญที่ user ยืนยัน:** ขยายฐานคนดูใหม่มาก่อน แล้วค่อยได้ผลพลอยได้
เรื่องลดคำถามจากลูกค้าที่ซื้อบัญชีไปแล้ว

หลังทำเสร็จ prod = **4 คลิป/วัน** — 12:00 · 15:00 (ใหม่) · 18:00 · 21:00

### ขอบเขต (ไม่ต่อรอง)

- **ห้ามแตะตะแกรง `ui_vocab`** ทุกกรณี คลิปยัง auto-publish โดยไม่มีคนดูก่อน
  ชื่อเมนูบนจอต้องมาจากคลังเท่านั้น (spec เดิม §10)
- **หน้าตาคลิปต้องเหมือนคลิป 21:00 เป๊ะ** ไม่สร้างระบบภาพชุดที่สอง
- ห้ามแก้พรอมป์ของอีก 3 ช่วงที่วิ่งอยู่ (`script`, `script_tutorial`, `script_case`)

## 2. ปัญหาแกน + แนวทางที่เลือก

ระบบปัจจุบันถูกออกแบบมา **กันเนื้อหาพื้นฐานโดยตั้งใจ**:

> `migrations/052:106` — "ห้ามเนื้อหาระดับพื้นฐานทั่วไป (basic ads 101, สอนสมัครบัญชี, สอนยิงแอดครั้งแรก)"
> `migrations/053:13` — "ใช้ศัพท์วงในได้เลยไม่ต้องนิยาม — คนดูรู้อยู่แล้ว"
> `script_tutorial` — "เสียงคนวงใน … ห้ามเนื้อหาระดับพื้นฐาน"

ดังนั้นคลิปพื้นฐานคือ **กลุ่มคนดูใหม่ที่ขัดกับกติกาเสียงของช่องปัจจุบัน** ต้องแยก
ไม่ใช่เพิ่มแถวในคลังเดิม

**แนวทางที่เลือก: แยก "เสียง" ออกจาก "หน้าตา"**

หน้าตาคลิป (layout, preset, นโยบายภาพ, ตะแกรง) ใช้ของโหมด tutorial ทั้งดุ้น
เปลี่ยนเฉพาะชุดพรอมป์ที่เขียนบท และคลังหัวข้อที่หยิบมาใช้

**แนวทางที่พิจารณาแล้วไม่เอา:**

- *สร้างโหมดที่ 4 เต็มรูปแบบ (`ModeBasic`)* — ต้องแก้ทุก `switch mode` ใน
  `internal/producer/case_format.go` (นโยบายภาพ, prompt ต่อซีน), template
  `[data-format]`, ตัวเลือก preset ทั้งที่ผลลัพธ์ต้องหน้าตาเหมือน tutorial เป๊ะ
  = พื้นที่ผิดพลาดเยอะโดยไม่ได้อะไรเพิ่ม
- *ยัดหัวข้อพื้นฐานเข้าคลัง `tutorial_features` เดิมเฉยๆ* — คลิป 21:00 (คนยิงหนัก)
  จะสุ่มได้ "CPM คืออะไร" ทำลายจุดขายของช่วงนั้น
- *เพิ่มกลุ่มเป้าหมายที่ 4 ใน `topic_categories`* — หมวดพวกนั้นถูกหมุนโดยรอบ
  12:00/18:00 ทำให้พื้นฐานไปโผล่ผิดช่วง และไม่ได้คลิปสอนจากหน้าจอ

## 3. สถาปัตยกรรม

### 3.1 แยก "โหมดภาพ" ออกจาก "โหมดพรอมป์"

ปัจจุบัน `clipMode(contentFormat)` ตอบคำถามสองข้อพร้อมกัน: หน้าตาเป็นแบบไหน และ
ใครเขียนบท ต่อไปแยกเป็นสองฟังก์ชัน

| ฟังก์ชัน | ตอบคำถาม | ค่าที่คืนสำหรับ `content_format = 'basic'` |
|---|---|---|
| `clipMode` (เดิม) | หน้าตา/preset/นโยบายภาพ | `ModeTutorial` — เหมือนคลิป 21:00 ทุกอย่าง |
| `agentModeFor` (ใหม่) | ใช้ prompt ชุดไหน | `"basic"` → หา row `script_basic` ฯลฯ |

`agentModeFor` แทนที่ `clipMode` **เฉพาะ 4 จุดที่หา agent config** เท่านั้น
(`orchestrator.go:318, 494, 513, 875`) จุดอื่นที่ใช้ `clipMode` ห้ามแตะ
เพราะนั่นคือเส้นทางภาพ

ผลพลอยได้: เส้นทาง retry (บรรทัด 875) ได้เสียงถูกชุดอัตโนมัติ เพราะ
`clips.content_format` ถูกเก็บไว้ในฐานข้อมูลอยู่แล้ว

### 3.2 คลังหัวข้อ — คิวแยก 2 สาย

เพิ่มคอลัมน์ `level` ใน `tutorial_features`

| ค่า | ใครใช้ | จำนวนตั้งต้น |
|---|---|---|
| `advanced` (ค่า default) | ช่วง 21:00 | 18 แถวเดิม |
| `basic` | ช่วง 15:00 | 12 แถวใหม่ |

`PickNext` รับพารามิเตอร์ `level` เพิ่ม → **สองช่วงมีคิวหมุนของตัวเอง มีพื้นกัน
คลังยุบของตัวเอง ไม่กวนกันเลย** กติกาเดิมทุกข้อ (least-used, two-strike,
`parked_until` หมดอายุ, พื้น `TutorialMinPool`) ใช้ต่อได้ทันทีโดยไม่ต้องแก้ตรรกะ

> **หมายเหตุพื้นคลัง:** `TutorialMinPool` = 10 ถูกตั้งไว้ตอนคลังมี 18 แถว
> คลัง basic มี 12 แถว พื้น 10 ยังใช้ได้ (พักได้สูงสุด 2 แถว) แต่ถ้าเติมหัวข้อ
> basic ไม่ถึง 12 ต้องทบทวนตัวเลขนี้ ไม่งั้นการพักจะถูกปฏิเสธแทบทุกครั้ง

### 3.3 เส้นทางผลิต

`ProduceBasic` = สำเนาโครงของ `ProduceTutorial` ที่ต่างกัน 3 จุด:

1. หยิบหัวข้อจากคลัง `level = 'basic'`
2. อ่าน content format ชื่อ `basic` (ไม่ใช่ `tutorial`)
3. `Category` ของคลิป = `beginner` (กลุ่มเป้าหมายใหม่ ดู §3.4)

ที่เหลือ — tracker, กติกา gate, การกันซ้ำมุม, การหมุน archetype/persona,
`MarkUsed` — เหมือนกันทุกอย่าง

**สิ่งที่ต้องระวัง (บทเรียนจาก `project_question_cooldown_deadlock`):** ทุกตัวกรอง
ที่ทำให้ "ไม่เหลือหัวข้อ" ต้อง fail-open ห้ามคืน 0 คลิปเงียบๆ — `level` เป็น
ตัวกรองใหม่ ต้องมีเทสต์ยืนยันว่าคลัง basic ว่าง ≠ ทำให้รอบ 21:00 พัง

### 3.4 เสียงคนพูด (แถวใหม่ใน `agent_configs`)

ต้องมี **ครบ 3 แถว** ห้ามพึ่ง fallback เพราะ `modeAgentConfig` จะตกกลับไป row
`script`/`scene`/`critic` ตัวฐาน ซึ่งเป็นเสียงคนวงในและไม่รู้จัก layout `uistep`

| แถว | ที่มา | สิ่งที่เปลี่ยน |
|---|---|---|
| `script_basic` | คัดลอกจาก `script_tutorial` | กลับด้านกติกาเสียง (ดูล่าง) |
| `scene_basic` | คัดลอกจาก `scene_tutorial` | เหมือนเดิมทุกอย่าง |
| `critic_basic` | คัดลอกจาก `critic_tutorial` | เพิ่มข้อ: ตีตกถ้ามีศัพท์ที่ไม่ได้นิยาม |

**กติกาเสียงของ `script_basic`** (แทนที่บล็อก "เสียงคนวงใน"):

- ศัพท์อังกฤษทุกคำที่โผล่ครั้งแรก ต้องมีคำอธิบายไทยสั้นๆ ต่อท้ายทันที
- ห้ามสมมติว่าคนดูเคยยิงแอดมาก่อน แต่**ห้ามพูดจาดูถูก** ("ง่ายมาก" "ใครๆ ก็ทำได้")
- ยกตัวอย่างด้วยเงินจำนวนน้อยที่คนเพิ่งเริ่มใช้จริง (หลักร้อยถึงหลักพันต่อวัน)
  ไม่ใช่หลักหมื่นแบบช่วงอื่น
- โครงบังคับ 6 ข้อของโหมดคู่มือ **คงไว้เหมือนเดิม** (เปิดด้วยความเสียหาย →
  สัญญา+จำนวนขั้น → เดินขั้นตอน → กับดัก → สรุป → ปิด) เพราะเป็นโครงที่ทำ
  retention ได้ ไม่ใช่เรื่องระดับความยาก
- คงกฎเหล็กเดิมไว้ทุกตัวอักษร: ชื่อเมนู/ปุ่ม/ฟิลด์ ต้องมาจาก `ui_vocab` เท่านั้น

**กลุ่มเป้าหมายใหม่** — เพิ่มแถว `beginner` ใน `topic_categories` แบบ
`enabled = FALSE` (เหมือนที่ `content_formats.tutorial` ทำ) เพื่อกันไม่ให้
`PickNextExclude` ของรอบ 12:00/18:00 หยิบไปใช้ แต่ยังมีข้อความ persona ให้
`ProduceBasic` อ้างถึงได้

### 3.5 ตารางเวลา

แถวใหม่ใน `schedules`: `produce_basic` · `0 15 * * *` · `enabled = FALSE`
(เปิดหลัง eyeball คลิปแรก) + `case "produce_basic"` ใน `scheduler.go`
+ endpoint `POST /api/v1/orchestrator/produce-basic` สำหรับยิงมือทดสอบ

**GOTCHA ที่ต้องจำ:** เปิด/ปิด schedule ต้อง PATCH ผ่าน API เท่านั้น
scheduler อ่าน DB แค่ตอน `Start()` — แก้ `enabled` ตรงใน DB จะไม่มีผลจนกว่าจะ restart

**ตรวจแล้วว่าไม่ชนกัน:** มีแถว `Afternoon TikTok` (`0 15 * * *`) อยู่ แต่
`enabled = FALSE` และ TikTok ถูกพักไม่มีกำหนด ถึงเปิดกลับก็ไม่ชน เพราะ
`publish_tiktok` ไม่ถือ production lock (มันเผยแพร่ ไม่ได้ผลิต)

## 4. คลังหัวข้อชุดแรก (12 แถว)

**อ่านรายงานให้เป็น**
1. อ่านคอลัมน์หลัก: Results / Reach / Impressions / Cost per result
2. Breakdown ดูผลแยกตามอายุ-เพศ
3. อ่านคอลัมน์ Delivery ว่าแอดวิ่งอยู่จริงไหม
4. เลือกช่วงวันที่ให้ถูก ทำไมตัวเลขเปลี่ยนตามวันที่ที่เลือก

**โครงสร้างที่คนงงที่สุด**
5. Campaign / Ad set / Ad อะไรอยู่ชั้นไหน
6. งบรายวัน vs งบตลอดอายุแคมเปญ
7. เลือกวัตถุประสงค์แคมเปญให้ตรงกับสิ่งที่อยากได้

**ฟีเจอร์พื้นฐานที่ต้องใช้จริง**
8. Boost post กับ Ads Manager ต่างกันตรงไหน
9. ตั้งกลุ่มเป้าหมายเบื้องต้น
10. ผูกเพจกับบัญชีโฆษณา
11. ตั้งวิธีชำระเงินครั้งแรก
12. ดูใบเสร็จและยอดที่ถูกตัดจริง

ทุกแถวต้องมี `steps` 3–5 ขั้น และ `ui_target` ทุกตัวอยู่ใน `ui_vocab` ของแถวนั้น
(บังคับด้วย `TestSeedStepsCoveredByUIVocab` ที่มีอยู่แล้ว — ต้องเพิ่มไฟล์ seed ใหม่
เข้าไปในตารางของเทสต์ตัวนั้น)

`pain_point` ของหัวข้อ basic **ไม่มีในเมนู 3 กลุ่มเดิม** (เมนูพวกนั้นเป็นปัญหา
ของคนยิงจริงจัง) จึงต้องมีชุด pain_point ของกลุ่ม `beginner` เอง อยู่ใน
`angle_instruction` ของแถวใหม่ ตามแบบเดียวกับ migration 057

## 5. การวัดผลและถอยกลับ

- แยกวัดได้ทันทีเพราะ `clips.content_format = 'basic'` — เทียบวิว/retention กับ
  `tutorial`, `qa`, `tips` ได้ตรงๆ
- ฐานเปรียบเทียบวันนี้ (21 วันล่าสุด, 62 คลิป): qa 21.2 วิว · tutorial 17.0 ·
  tips 7.3 · case_story 3.4 · news 2.3 · **คอมเมนต์ 0 ทุกคลิป**
- **เกณฑ์ตัดสินหลัง 2 สัปดาห์:** ถ้าวิวเฉลี่ยของ basic ไม่เกินค่ามัธยฐานของ
  format อื่น ให้ปิด schedule แล้วทบทวน ไม่ใช่เติมหัวข้อเพิ่ม
- **Rollback:** ปิดแถว schedule ตัวเดียว (PATCH `enabled=false`) คลิปที่ผลิตไปแล้ว
  ไม่กระทบ · ถอนสุดทาง = revert commit + `ALTER TABLE tutorial_features DROP COLUMN level`

## 6. ไม่ทำในรอบนี้ (YAGNI)

- ไม่ทำ UI หน้าจัดการคลังหัวข้อ — แก้ผ่าน SQL/migration เหมือนเดิม
- ไม่ทำ agent คิดหัวข้อพื้นฐานเอง — คลัง 12 แถวพอสำหรับ 12 วัน ค่อยตัดสินใจ
  หลังเห็นตัวเลขจริง (ตัดสินใจร่วมกับ user 28 ก.ค.: ที่วิว 2–21/คลิป
  การซ้ำยังไม่ใช่คอขวด)
- ไม่ทำโหมดภาพชุดใหม่ — ใช้ `TutorialPreset` เดิม
- ไม่แตะบั๊กเครดิต kie ที่เจอระหว่างสำรวจ (kie ส่ง `14070.59` เป็นทศนิยม แต่โค้ด
  รับ `int` → อ่านไม่ออก รายงานเป็น `-1` ทำให้ตัวกันผลิตตอนเครดิตหมดไม่ทำงาน)
  **แยกเป็นงานต่างหาก** ไม่เกี่ยวกับช่วง 15:00 แต่ควรแก้ก่อนเพิ่มเป็น 4 คลิป/วัน
  เพราะการใช้เครดิตจะเพิ่มขึ้น 33%
