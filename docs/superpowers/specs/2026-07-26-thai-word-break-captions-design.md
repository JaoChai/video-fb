# แก้คำภาษาไทยถูกหั่นกลางคำในแคปชั่น

วันที่ 2026-07-26 · ที่มา: backtest Gemini visual QA 26 คลิป (246 ซีน) พบว่า **14 จาก 19 ตำหนิจริง**
เป็นคำถูกหั่นกลางคำ และยังเกิดกับคลิปวันที่ 20–22 ก.ค. คือยังพังอยู่ ณ วันที่เขียนสเปคนี้

## ปัญหา

ผู้ชมเห็นคำขาดกลางคำในกล่องแคปชั่น เช่น `แอดมินอ` / `ยู่` · `ตัวตนผู้จ่` / `ายเงิน` · `เป็นปัญห` / `าแบบนี้`
มีสองต้นเหตุที่แยกกันคนละชั้น ทั้งคู่ยืนยันด้วยการทดลองแล้ว

### ชั้น A — โค้ดฝั่ง Go หั่นวลีกลางคำ

`splitCaptionPhrases()` ใน `internal/producer/captions.go` ตัดข้อความที่ยาวเกิน 42 ตัวอักษรแบบดิบ
`safeCut()` กันได้แค่สระบน/ล่างและวรรณยุกต์ (Unicode Mn) ไม่ได้กันการตัดกลางคำ
เพราะ `า` `อ` `ง` `ย` เป็นพยัญชนะ/สระเดี่ยวที่ตัดผ่านได้

ผลคือคำขาด **ข้ามเฟรม** — ผู้ชมเห็น `…แอดมินอ` ค้างจนจบวลี แล้ววลีถัดไปขึ้นต้นด้วย `ยู่…`
จำลองฟังก์ชันนี้กับ `voice_text` จริงแล้วได้รอยตัดตรงกับที่เห็นในภาพ 6 จาก 6 เคสที่สุ่มตรวจ
วัดกับทั้ง 26 คลิป: **49 จาก 246 ซีน (20%) โดนหั่นกลางคำ**

### ชั้น B — พจนานุกรมไทยของ Chromium ไม่รู้จักคำทับศัพท์

ทดสอบด้วย Chromium จริง (Playwright) ในกล่องขนาดเดียวกับ production (กว้าง 838px ฟอนต์ 48px):
`Intl.Segmenter('th')` แบ่ง `แอดมินอยู่` เป็น `แอด|มิ|นอ|ยู่` และ layout ขึ้นบรรทัดตามนั้น

จุดสำคัญคือคำทับศัพท์ที่ไม่รู้จัก **ทำให้คำไทยข้างเคียงถูกแบ่งผิดไปด้วย** — รอยตัด `แอดมินอ|ยู่`
ไม่ได้อยู่ใน `แอดมิน` แต่อยู่กลางคำ `อยู่` เพราะ ICU มองว่า `น`+`อ` รวมเป็น `นอ`

สแกนคำในโดเมนนี้ 63 คำ พบว่า **40 คำถูกแบ่งผิด** และ 24 คำในนั้นปรากฏจริงในเนื้อหา 982 ซีน
คำที่บ่อยที่สุดคือชื่อแบรนด์เอง: `แอดส์แวนซ์` 225 ครั้ง (อยู่ใน CTA ทุกคลิป) ถูกซอยเป็น `แอด|ส์|แวน|ซ์`

CSS ไม่ช่วย — ทดสอบ `overflow-wrap:break-word` (ของเดิม), ไม่ใส่เลย, `word-break:keep-all`,
`word-break:auto-phrase` ได้รอยตัดเหมือนกันทั้งสี่แบบ

## ทางแก้

### ชั้น A: เลิกหั่นเอง

ลบการ hard-split ออกจาก `splitCaptionPhrases()` — token ที่ยาวเกิน `captionMaxRunes` ปล่อยเป็นวลีเดียว
ให้ Chromium จัดการขึ้นบรรทัดแทน `safeCut()` จะไม่มีผู้เรียกอีกและถูกลบไปด้วย

ผลกระทบวัดจากเนื้อหาจริง 26 คลิป:

| | ปัจจุบัน | หลังแก้ |
|---|---|---|
| จำนวนวลีทั้งหมด | 700 | 664 (−5%) |
| ความยาววลีเฉลี่ย | 29 ตัวอักษร | 31 |
| p90 | 42 | 42 |
| ยาวที่สุด | 42 | 67 |

จังหวะคาราโอเกะแทบไม่เปลี่ยน เพราะวลียาวเป็นส่วนน้อย มีเพียง 128 จาก 664 วลี (19%) ที่ยาวพอต้องขึ้นบรรทัด

### ชั้น B: แทรก zero-width space คร่อมคำทับศัพท์

ทดสอบสี่วิธีกับ Chromium จริง:

| วิธี | ผล |
|---|---|
| word joiner (U+2060) ระหว่างตัวอักษรในคำ | `แอดมินอ｜ยู่` — ยังผิด |
| span `white-space:nowrap` เฉพาะคำนั้น | `แอดมินอ｜ยู่` — ยังผิด |
| **ZWSP (U+200B) คร่อมคำ** | **`แอดมิน｜อยู่` — ถูก** |
| ZWSP คร่อม + word joiner ในคำ | ถูก แต่ซับซ้อนกว่าโดยไม่ได้อะไรเพิ่ม |

เลือก ZWSP คร่อมคำ เพราะเป็นการแทรกอักขระล้วน ทำฝั่ง Go จุดเดียว ไม่ต้องแตะ CSS, markup หรือ JS
และใช้ได้กับข้อความทุกชนิดไม่ใช่แค่แคปชั่น ทดสอบแล้วความสูงกล่องไม่เปลี่ยน (185px เท่าเดิม)

## หน่วยที่แก้

### 1. `internal/producer/captions.go` (แก้)

ตัด branch hard-split ใน `splitCaptionPhrases()` ออก และลบ `safeCut()`

### 2. `internal/producer/thaiwrap.go` (ใหม่)

หน่วยเดียว หน้าที่เดียว ไม่มี dependency:

- `thaiLoanWords` — รายการคำทับศัพท์ที่ ICU แบ่งผิดและพบจริงในเนื้อหา **เรียงจากยาวไปสั้น**
  เพื่อให้คำประกอบชนะคำย่อย (`ไอดีแอดส์แวนซ์` ต้องมาก่อน `แอดส์แวนซ์` และ `ไอดี`)
- `GuardLoanWords(s string) string` — แทรก `​` คร่อมทุกคำที่พบ
  - เป็น pure function ไม่มี error path; สตริงว่างคืนค่าเดิม
  - **idempotent** — เรียกซ้ำต้องไม่แทรกซ้อน (ข้ามตำแหน่งที่มี ZWSP ประกบอยู่แล้ว)
  - ไม่แตะคำที่ไม่อยู่ในรายการ

รายการคำตั้งต้น (ความถี่ที่นับได้จาก 982 ซีน):

```
ไอดีแอดส์แวนซ์ 44 · แอดส์แวนซ์ 225 · ไอดี 51 · เทเลแกรม 50 · แอดมิน 30 · เฟซบุ๊ก 29
เอเจนซี่ 20 · คอมเมนต์ 15 · เมต้า 14 · ลิมิต 10 · บีเอ็ม 9 · คอนเวอร์ชัน 5 · ซีบีโอ 5
แชทบอท 4 · พอร์ตโฟลิโอ 3 · เพย์เมนต์ 3 · โอทีพี 2 · ฟีด 2 · รีช 2 · เฟสบุ๊ก 2
แอคเคาน์ 2 · แดชบอร์ด 2 · เอบีโอ 1 · อัลกอริทึม 1 · ไอพี 1
```

ความถี่นับแบบซ้อนกันได้ — `แอดส์แวนซ์` 225 ครั้งนั้นรวม 44 ครั้งที่อยู่ในรูป `ไอดีแอดส์แวนซ์` ด้วย
จึงต้องเรียงคำยาวไว้ก่อน

เก็บเป็นค่าคงที่ในโค้ด (ผู้ใช้เลือก) — เพิ่มคำใหม่ต้อง deploy แต่คำใหม่เกิดไม่บ่อย

### 3. จุดเรียก

สองจุด ทั้งคู่อยู่หลังจากเส้นทาง TTS แยกออกไปแล้ว:

1. **แคปชั่น** — ใน `captionSegmentsFromScenes()` ตอนประกอบ `TranscriptSegment.Text`
   (ผู้เรียกคือ `producer.go:430` ซึ่งรับผลมาหลัง TTS ทำงานเสร็จแล้ว)
2. **ข้อความบนจอ** — ใน `clean()` ของ `scene_adapter.go` ซึ่งเป็นจุดที่ข้อความทุกช่อง
   (`Title`, `Sub`, `CTA`, `Pill`, `Chips`, `StatLabel`, `Hook`) ผ่านอยู่แล้ว ทำให้ครอบคลุมโดยไม่ต้องไล่แก้ทีละช่อง

ข้อควรระวังของจุดที่ 2: `Title`/`Hook` ผ่าน `highlightTitleStr()` ซึ่งห่อคำ emphasis ด้วย `<span class="acc">`
ต้อง **guard หลัง highlight** เพื่อไม่ให้ ZWSP ไปขวางการจับคู่คำ emphasis
และต้องไม่แทรก ZWSP เข้าไปในแท็ก HTML

**ห้ามเรียกกับข้อความที่ส่งเข้า TTS** `voice_text` เดียวกันถูกใช้ทั้งทำเสียงและทำแคปชั่น
ZWSP ต้องแทรกหลังสองเส้นทางแยกกันแล้วเท่านั้น

## ทางเดินข้อมูล

```
voice_text (DB)
 ├─→ splitVoiceText → TTS            ข้อความดิบ ไม่มี ZWSP
 └─→ captionSegmentsFromScenes
      └→ splitCaptionPhrases          ไม่ซอยกลางคำแล้ว
         └→ GuardLoanWords            แทรก ZWSP คร่อมคำทับศัพท์
            └→ SEGMENTS ใน HTML → Chromium ขึ้นบรรทัดตรงขอบเขตคำ
```

## การจัดการข้อผิดพลาด

`GuardLoanWords` ไม่มีทางล้มเหลว: ไม่มี I/O ไม่มี allocation ที่ล้มได้ ไม่มี error return
กรณีขอบที่ต้องรองรับ — สตริงว่าง, ข้อความที่ไม่มีคำในรายการ, คำซ้อนกัน, ข้อความที่ผ่านฟังก์ชันนี้มาแล้ว

ความเสี่ยงที่แท้จริงอยู่ที่ **ZWSP รั่วไปเส้นทางอื่น** ไม่ใช่ที่ตัวฟังก์ชัน:
เข้า TTS (เสียงเพี้ยน), เข้า title/description ตอน publish (ขึ้น YouTube เป็นอักขระแปลก),
เข้า visual QA prompt (โมเดลอาจสับสน) — ทั้งสามต้องมีเทสต์กัน

## การทดสอบ

1. **golden test จาก backtest** — ใช้ `voice_text` จริงของ 6 ซีนที่พังจริง
   (`แอดมินอ|ยู่`, `บัญชีที่เค|ยมีปัญหา`, `ของทั้|งบัญชี`, `เป็นปัญห|าแบบนี้`, `ขาดไม่ไ|ด้`, `ตัวตนผู้จ่|ายเงิน`)
   ยืนยันว่าไม่มีวลีไหนจบหรือขึ้นต้นกลางคำอีก
2. `GuardLoanWords` — แทรกถูกตำแหน่ง · เรียกซ้ำไม่แทรกซ้อน · คำประกอบชนะคำย่อย · ไม่แตะคำนอกรายการ
3. **ZWSP ไม่รั่วไป TTS** — ยืนยันว่าข้อความที่เข้า `splitVoiceText` ไม่มี `​`
4. render test — HTML ที่ได้มี ZWSP ในตำแหน่งที่คาด และไม่มีใน element ที่ไม่ควรมี
5. verify จริง — render 1 คลิปแล้วเทียบเฟรมก่อน/หลังด้วยตา

## สิ่งที่ยอมรับและไม่ทำ

- วลีที่ยาวที่สุดจะเป็น 67 ตัวอักษร ทำให้กล่องแคปชั่นสูงได้ถึงราว 250px จากเดิมสูงสุด 185px
  ต้องยืนยันตอน render ว่าไม่บังเนื้อหา ถ้าบัง จะลด `captionMaxRunes` ลงแทนการกลับไปหั่นกลางคำ
- ไม่ re-render คลิปเก่าที่เผยแพร่ไปแล้ว
- ไม่ใส่ feature flag — ขอบเขตเล็กและ revert commit ได้ทันที
- ไม่แตะ visual QA, การเลือกวลีของ TTS หรือ layout อื่น
- คำทับศัพท์ที่ยังไม่อยู่ในรายการจะยังตัดผิดได้ ยอมรับไว้ก่อนแล้วเติมเมื่อเจอ
